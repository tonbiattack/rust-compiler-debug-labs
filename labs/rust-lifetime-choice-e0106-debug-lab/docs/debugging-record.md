# E0106 調査記録：複数入力参照の返り値

## 目的

二つの入力ラベルから条件に応じた参照を返す契約を、Rust 1.75.0で確認します。

## 実行環境と再現境界

| 項目 | 内容 |
| --- | --- |
| 失敗コマンド | `cargo check` |
| 成功コマンド | `cargo test` |
| 再現境界 | 二つの`&str`入力から`&str`を返す関数署名 |

## 最初に観測した事実

`cargo check`は終了コード101でE0106を出し、返り値が`primary`と`fallback`のどちらから借用されるかを署名が示さないと報告しました。記録は`docs/observed-cargo-check-bug.txt`です。

## 競合仮説と検証

| 仮説 | 検証 | 結果 |
| --- | --- | --- |
| `if`の返し方が問題 | 寿命だけを明示して同じ分岐を維持する | 棄却。分岐は変えずに成功しました。 |
| 出力の借用元が曖昧 | 二入力と出力に同じライフタイムを付ける | 支持。E0106が消えました。 |

## 確定した原因

E0106は型に必要なライフタイムがないときに発生します。複数の入力参照がある関数では、出力参照の寿命を省略規則で一意に決められない場合があります。[Rust error code E0106][1]

## 最小修正

```rust
pub fn active_label<'a>(primary: &'a str, fallback: &'a str) -> &'a str
```

この関数では返り値が二つの入力の共通寿命を越えないことを表します。修正コミットは `e79d0be` です。

## 回帰保証

主ラベルと既定ラベルを返す二つの統合テストが成功しました。

## 再現手順

```bash
git switch --detach 2c29836
cargo check
git switch main
cargo test
```

## スコープと注意点

`'a`は値の寿命を延ばしません。入力のどちらかが先に失効する呼び出しでは、その時点より長く返り値を使えません。
