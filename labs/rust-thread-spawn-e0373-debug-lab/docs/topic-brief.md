# 題材メモ：`thread::spawn` のクロージャ捕捉で発生する E0373

## 対象

| 項目 | 内容 |
| --- | --- |
| 対象言語 | Rust 1.75.0 |
| 対象読者 | 所有権とクロージャの基本を学んだ、Rust初学者〜初中級者 |
| 難易度プロファイル | 実践・上級 |
| 選定理由 | `thread::spawn` へ渡すクロージャの借用と `'static` 制約が交差するため、`move` を単なる定型句として覚えず、コンパイラ診断から理由を追える題材です。 |
| 実行基盤 | Cargo 1.75.0 と Rust標準ライブラリ。外部依存はありません。 |
| フレームワーク非依存性 | `std::thread::spawn` とクロージャだけで再現し、Webフレームワークや非同期ランタイムを使いません。 |

既存のRust記事は所有権移動の E0382、不変・可変借用の E0502、ライフタイムの E0597 を扱っています。本題材は、別スレッドへ渡すクロージャがローカル変数を参照捕捉したときの E0373 と `thread::spawn` の `'static` 制約を扱うため、失敗条件、原因、修正の中心が異なります。

## 学習する契約

> 入力 `String` を `complete_in_worker` に渡したとき、期待する結果はワーカースレッドが生成する完了メッセージですが、バグ状態ではクロージャが `String` を参照捕捉して E0373 でコンパイルに失敗します。

### 対象の直接原因

`thread::spawn` に渡すクロージャは実行元の関数より長く生存し得るため `'static` を満たす必要があります。`format!` による利用では既定で `label` を参照捕捉するため、そのままではローカルの `String` を別スレッドへ安全に渡せません。

### 対象外

`Arc`、`Mutex`、複数スレッド間の共有可変状態、スコープ付きスレッド、asyncブロック、スレッドスケジューリングの順序は扱いません。

## 再現設計

| 要素 | 決定 |
| --- | --- |
| 公開境界 | `complete_in_worker(label: String) -> String` |
| 入力・初期状態 | `"月次集計".to_owned()`。外部状態を使いません。 |
| Redの観測 | `cargo test` または `cargo check` が E0373 を出して失敗します。 |
| 最終観測 | 統合テストがワーカースレッドから返すメッセージを直接検証します。空文字列の対照ケースも検証します。 |
| 決定性 | スレッド終了を `JoinHandle::join` で待機し、`sleep` は使いません。 |
| 固定状態の検証コマンド | `cargo test` |
| バグ状態の確認コマンド | `cargo check` |

## 仮説

| 仮説 | どう検証または除外するか |
| --- | --- |
| 主仮説：`label` が参照捕捉され、`thread::spawn` の `'static` 制約を満たせない | E0373の診断にある借用箇所、`'static` を要求する箇所、`move` の提案を確認します。 |
| 競合仮説：`join` を呼んでいないために失敗している | `join` をすでに呼んでいる状態でE0373が発生すること、および公式E0373説明で`join`だけでは受理されないことを照合します。 |
| 競合仮説：スレッドが値を扱えないこと自体が原因である | `move` を追加すると同じ値・同じスレッド処理でコンパイルとテストが通ることを確認します。 |

## 予定する履歴

| 順序 | コミットの目的 | 期待する状態 |
| --- | --- | --- |
| 1 | `thread::spawn` のE0373を再現する | `cargo check` と `cargo test` が E0373 で失敗します。 |
| 2 | ワーカースレッドへ値の所有権を渡す | 同じテストが成功し、全体も成功します。 |
