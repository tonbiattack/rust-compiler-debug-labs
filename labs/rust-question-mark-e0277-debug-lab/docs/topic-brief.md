# 題材メモ：`?`演算子のエラー変換で発生する E0277

| 項目 | 決定 |
| --- | --- |
| 対象 | Rust 1.75.0、`Result<u16, String>` を返す関数内の `?` 演算子 |
| 契約 | `"8080"` を渡すと `Ok(8080)` を返し、不正な入力には読みやすいエラーを返す。 |
| Red | `ParseIntError` を `String` へ変換できず、`cargo check` が E0277 で終了コード101になる。 |
| 直接原因 | `?` が要求する `From<ParseIntError> for String` が存在しない。 |
| 最小修正 | `map_err` で解析エラーを関数の戻りエラー型へ明示的に変換する。 |
| 最終観測 | 成功入力のポート番号と、不正入力のエラーメッセージを統合テストで確認する。 |

既存記事にある E0277 はスライスが `Sized` を実装しない事例です。本題材は `?` 演算子が行うエラー変換と `From` トレイト境界を扱うため、失敗条件と修正の中心が異なります。
